<section>
<div class="grp">The fingerprint</div>
<div class="g"><div class="g-head"><span class="term">fingerprint</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Verifier/Assemble.lean">Verifier.Assemble.assemble</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Fingerprint/Match.lean">Fingerprint.Match.msmMatch_eval</a></span></div><div class="def">The whole verifier collapsed into one multi-scalar multiplication; the proof accepts exactly when that MSM is the group identity. <div class="g"><div class="g-head"><span class="term">match-only capture</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Fixtures/SingleAction/Random/Boundary.lean">Fixtures.SingleAction.Random.Boundary</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Fixtures/SingleAction/Random/Boundary.lean">nonInteractiveFingerprint_matches_derived</a></span></div><div class="def">A capture of the deployed verifier run on a <em>random</em> proof string: deliberately non-accepting, it witnesses coefficient-for-coefficient agreement without an accepting run. <div class="g"><div class="g-head"><span class="term">deployed acceptance</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Main.lean">Main.DeployedAccepts</a></span></div><div class="def">The concrete verifier decision: the MSM assembled from the proof, instances, verifying key, and derived challenges evaluates to the group identity.</div></div>

</section>

<section>
<div class="grp">Fiat–Shamir &amp; oracle execution</div>
<div class="g"><div class="g-head"><span class="term">querying adversary</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Common/Oracle/OracleComp.lean">Common.Oracle.OracleComp</a></span></div><div class="def">An adaptive oracle-query computation with eager whole-table semantics, an explicit query bound, and a log of the points read on each execution. <div class="g"><div class="g-head"><span class="term">IPA splice</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/FiatShamir/Execution.lean">FiatShamir.Execution.spliceIpa</a></span></div><div class="def">Replacing only a proof's IPA fields while preserving the pre-IPA proof data. <div class="g"><div class="g-head"><span class="term">round-by-round soundness</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/FiatShamir/Ordering.lean">FiatShamir.Ordering</a></span></div><div class="def">The transcript-ordering guarantee: each IPA round point sits in the transcript prefix before its challenge is drawn, so later messages cannot bend earlier challenges.</div></div>
<div class="g"><div class="g-head"><span class="term">challenge-conversion bias</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Oracle/Challenge255.lean">Oracle.Challenge255.challenge255Bias</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Common/Oracle/Model.lean">PMFEventBiasLE</a></span></div><div class="def">The security layer prices squeezes as exactly uniform; the deployed <code>Challenge255</code> conversion instead reduces a 64-byte digest modulo $p$. With the digest idealized as uniform, an event's probability exceeds its uniform value by at most $r(p-r)/(p \cdot 2^{512}) < 2^{-260}$, where $2^{512} = qp + r$ — the exact constant, attained by the heavy residues, stated as the <code>PMFEventBiasLE</code> premiss the transport theorem and the work-factor capstone's bias conjunct consume. Idealizing BLAKE2b as the uniform digest stays external.</div></div>
</section>

<section>
<div class="grp">Binding &amp; the AGM</div>
<div class="g" id="algebraic"><div class="g-head"><span class="term">algebraic</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Common/DiscreteLogRelation.lean">Common.DiscreteLogRelation.AlgebraicPoint</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/AGM/OnlineMembers.lean">AGM.OnlineMembers.OnlineMemberProofData</a></span></div><div class="def">An adversary that supplies, with every group element it outputs, a representation: coefficients expressing that element over the elements it has received. Only the provenance of outputs is restricted — the computation choosing the coefficients may use any structure it can see. The restriction is part of the adversary's <em>type</em>, and every generic adversary is algebraic. See <a href="security-models.html#the-algebraic-adversary-restriction">the algebraic-adversary restriction</a> for what supports the heuristic.</div></div>
<div class="g" id="programmed-basis"><div class="g-head"><span class="term">programmed-basis</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Common/ProgrammedBasis.lean">Common.ProgrammedBasis.ProgrammedBasisEmbedding</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Common/ProgrammedBasis.lean">ProgrammedRelationOutcome</a></span></div><div class="def">Program every basis slot from the discrete-log challenge as $x \,•\, B + y \,•\, C$ with fresh uniform pairs (Jaeger–Tessaro, Lemma 3). The reduction restricts how the basis is sampled, not the adversary: it consumes relation coefficients from any source, so it carries no AGM scoping. A relation with nonzero challenge component yields the discrete log of the challenge; a miss retains the exact same returned relation and proves it annihilates the programming — a single $1/\FieldSize$ hyperplane, with no slot guess and no $|\mathrm{basis}|$ factor.</div></div>
<div class="g" id="generator-ro"><div class="g-head"><span class="term">generator-RO</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/AGM/ProbabilityVesta.lean">orchardGeneratorROSetup</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/AGM/ProbabilityVesta.lean">orchardGeneratorROBasis</a> ·&nbsp;*_generatorRO*</span></div><div class="def">A modelling ingredient of the discrete-log endpoints: the reference-string generators are drawn from a programmable random oracle, so the programmed-basis reduction can embed its discrete-log challenge into the basis. Named with <code>generatorRO</code> wherever it applies, from the oracle setup and basis constructions to the capstones stated in this modelling.</div></div>
<div class="g" id="urs"><div class="g-head"><span class="term">Uniform Reference String (URS)</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Arithmetic/Group.lean">Arithmetic.Group.URS</a></span></div><div class="def">A reference string of uniformly distributed group elements, with no hidden structure or trapdoor. The deployed protocol produces its URS once, by hashing public strings to the curve (<code>GroupHash</code>, spec <a href="https://zips.z.cash/protocol/protocol.pdf#concretegrouphashpallasandvesta">§5.4.9.8</a>), and the security statements sample it instead via the <a href="#generator-ro">generator-RO</a>. The gap between the two —including the protocol-lifetime caveat— is discussed under <a href="security-models.html#fixed-bases-the-group-hash-and-the-reference-string">fixed bases, the group hash, and the reference string</a>.</div></div>
<div class="g"><div class="g-head"><span class="term">straight-line AGM extractor</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/AGM/StraightLinePinnedRoots.lean">AGM.StraightLinePinnedRoots.StraightLineIpaOnlineTrace</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Composition/StraightLineDeployed.lean">Composition.StraightLineDeployed.ComputedStraightLineDeployedFSFamily.ofCovered</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Composition/StraightLineConstraint.lean">Composition.StraightLineConstraint</a></span></div><div class="def">The deployed AGM route. Each IPA round exposes an executable pre-squeeze polynomial computation, proves that it has not queried that round's squeeze point, and connects its result to the final proof. One accepting transcript therefore yields a clean decode, explicit DLOG relation, or pinned quadratic event. The combined finder uses at most four prover invocations, so no expected-runs truncation or Markov tail appears anywhere in the bound. <code>ofCovered</code> packages the representation-carrying online prover with caller-supplied executable root, IPA, and constraint-$x$ stages plus freshness proofs; the captured endpoint applies existing verifier metadata without a new proof fixture. The representations exist only in the model —the algebraic adversary supplies them alongside its proof, and the extractor reads them— and are never Halo2 proof bytes; this is an AGM-and-random-oracle result. The verifying key, instance commitments, and initial transcript prefix are fixed per basis before oracle access. Only the adaptive-statement capstone permits online statement choice.</div></div>
<div class="g" id="shallow"><div class="g-head"><span class="term">shallow cost language</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/AGM/CostedOracle.lean">AGM.CostedOracle.CostedLabeledOracleComp</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/AGM/CostedOracle.lean">CostedLabeledOracleComp.StagedGroupWorkFaithful</a></span></div><div class="def">The group-work accounting language reifies as explicit syntax only the group operations a program writes as nodes. Everything else — the Lean terms building <code>pure</code> payloads, query arguments, and continuations — stays in the host language, where Lean has no operational cost semantics. That is what <em>shallow</em> means here, and the price of it is that the counter measures what was staged rather than what the host computes: group law performed inside an unreified callback would go uncharged. <code>StagedGroupWorkFaithful</code> is the judgement that no such work exists, which is why it is a named premiss carried into the endpoints rather than a theorem. A deep embedding — host computation reified as syntax too — would discharge it in Lean, at the cost of rewriting the reduction in that syntax.</div></div>
<div class="g" id="adv-dlog"><div class="g-head"><span class="term">DL reduction bound</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Common/RelationProbability.lean">Common.RelationProbability.TextbookDLAdvantageLE</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/AGM/CostedOracle.lean">AGM.CostedOracle.CostedLabeledOracleComp</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Action/AdaptiveStatementCost.lean">Action.AdaptiveStatementCost.CertifiedAdaptiveStatementDlogProfile</a></span></div><div class="def">The programmed-basis reduction turns a computed relation into either a discrete-log solution or one $1/|\mathbb{F}_p|$ miss hyperplane. The adaptive route uses a staged cost language whose erasure is the original algebraic adversary. One closed program constructs the charged basis, specializes the exact adversary path while retaining its annotation log and group nodes, builds a proof-carrying cache from that result, and feeds the same cache into charged verifier postprocessing. Lean proves that this program's counter is the adversary counter plus the reified reduction counter; no separate arithmetic join or second adversary execution remains. $\mathrm{Adv}_{\mathrm{DLOG}}$ is written throughout with two resource arguments, $\mathrm{Adv}_{\mathrm{DLOG}}(q, g)$: $q$ is the adversary's random-oracle query count and $g$ its group-operation count, the latter charging the adversary and the reduction together (<code>AdaptiveStatementDlogProfile.advantage</code>, applied at <code>adaptiveStatementDlogRandomOracleQueries</code> and <code>adaptiveStatementDlogGroupWork proverGroupWork reductionGroupWork</code>). At $Q \le 2^{123}$, the endpoints bound failure by $\mathrm{Adv}_{\mathrm{DLOG}}(2^{124}, 2^{126}) + 2^{-83}$ for either a $2^{123}$ or $2^{125}$ adversary group-work budget; the latter's adversary-plus-reduction group work is at most $2^{126}$. Equality/list traversal, direct-coordinate work, and random-oracle queries are separate resources. The three-decode bound follows from a required family representation-length invariant; the generic theorem does not construct a concrete deployed family. Because the language is <a href="#shallow">shallow</a>, staging fidelity remains explicit both for the external adversary and for host computations inside the complete program, such as generic key construction, hashing, and fixed-representation callbacks. These numbers are coverage parameters, not a claim that Lean computes Vesta's DLOG advantage.</div></div>
</section>

<div class="g"><div class="g-head"><span class="term">x-squeeze schedule · εₓ</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Composition/ScheduleBudget.lean">Composition.ScheduleBudget</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Fixtures/MultiAction/Honest/Schedule.lean">Fixture2.deployedConstraintXSqueezeSchedule_captured</a></span></div><div class="def">The straight-line pricing of the constraint-evaluation challenge: the pre-$x$ constraint difference's root set is capped by the degree walk — $\varepsilon_x = 20470/\FieldSize$ at the captured key, consumed as $(Q+1) \cdot \varepsilon_x$. <section>
<div class="grp">Capstones</div>
<div class="g"><div class="g-head"><span class="term">capstones</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Capstones/Action.lean">Capstones/Action.lean</a></span></div><div class="def">The adaptive-statement capstones prove a knowledge-failure bound for the deployed Action verifier against represented online algebraic adversaries, with Fiat–Shamir challenge derivation modelled as a random oracle. The adversary chooses the public statement and proof together, and the selected instance prefix is bound before $\theta$. For every consensus-valid Action count, a faithfully staged adversary bounded by $2^{125}$ group operations has failure probability at most $\mathrm{Adv}_{\mathrm{DLOG}}(2^{124}, 2^{126}) + 2^{-83}$ (<a href="#adv-dlog">arguments</a>), provided $Q \le 2^{123}$. Erasure preserves the original game; one composed program value-threads the exact adversary path and cache through the reduction; and Lean checks the counter decomposition and $2\times$ arithmetic. The result remains conditional on two explicit shallow-language fidelity obligations: the supplied adversary program and the complete program's host callbacks must perform no hidden Vesta group work. Its three-decode bound is conditional on the family's required representation-length invariant, which is not a concrete deployment instance constructed here. The quoted powers are resource coverage —not a universal failure ceiling— and the result does not cover arbitrary non-algebraic adversaries or concrete BLAKE2b. The random oracle ranges over bounded transcripts of the deployed schedule; AGM representations accompany every query but are erased before the oracle answers. The family fixes its key digest and verifier representations per basis before oracle access, and bundle size is public, universally quantified up to the consensus maximum.</div></div>
<div class="g"><div class="g-head"><span class="term">knowledge-failure event</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Action/AdaptiveStatementKnowledge.lean">ComputedAdaptiveActionStatementFSFamily.adaptiveStatementKnowledgeFailureEvent</a></span></div><div class="def">The event that the deployed Action verifier accepts but the executable extractor does not return private witnesses for the entire bundle. <div class="g"><div class="g-head"><span class="term">semantic residuals</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Action/AdaptiveStatementEvent.lean">ComputedAdaptiveActionStatementFSFamily.semanticEvent</a></span></div><div class="def">The explicitly priced $y$, $\beta$, $\gamma$, and $\theta$ challenge surfaces needed to promote the compressed constraint identity to row-level gate, permutation, and lookup semantics.</div></div>
<div class="g"><div class="g-head"><span class="term">ledger composition · deployment provenance</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Soundness/Action/StraightLineTerminal.lean">ActionBundleWitness</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Security/Ledger/Bridge.lean">actionSpec_to_ledger</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Snark/Keygen/Certificate.lean">Keygen.Certificate</a></span></div><div class="def">The capstone returns the deployed Action circuit's private witnesses and satisfaction proofs, and actionSpec_to_ledger already refines one such Action witness to the games-facing ledger statement or an exhibited break. The remaining output-side floor is composing every extracted bundle entry through that bridge. <section>
<div class="grp">Binding-signature balance — value preservation</div>
<div class="g"><div class="g-head"><span class="term">balance</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Security/BindingSignature/Balance.lean">Security.BindingSignature.Balance</a></span></div><div class="def">No transaction creates or destroys value (spec §4.13 Sapling / §4.14 Orchard). Value commitments are <code>cv v rcv</code> $= v \,•\, \mathcal{V} + \mathsf{rcv} \,•\, \mathcal{R}$; a bundle's binding verification key collects to $\mathsf{bvk} = A \,•\, \mathcal{V} + B \,•\, \mathcal{R}$ with $A$ the net value imbalance. The property is <em>not</em> "no discrete-log relation between $\mathcal{V}$ and $\mathcal{R}$ exists" —one always does in a prime-order group— but the reduction in the <code>NontrivialRelation</code> card below.</div></div>
<div class="g"><div class="g-head"><span class="term">NontrivialRelation</span><span class="anchor"><a href="https://github.com/zcash/ironwood/blob/main/Zcash/Security/BindingSignature/Balance.lean">Security.BindingSignature.NontrivialRelation</a> ·&nbsp;<a href="https://github.com/zcash/ironwood/blob/main/Zcash/Security/BindingSignature/Balance.lean">.ofImbalance</a></span></div><div class="def">The break, as computed data: a nontrivial $\mathbb{F}$-linear relation between the value base <code>Vbase</code> ($\mathcal{V}$) and randomness base <code>Rbase</code> ($\mathcal{R}$), with its coefficients explicit — equivalently the discrete log <code>dlog_Rbase Vbase</code> (<code>imbalance_yields_discrete_log</code>). One always exists at prime order, so an ∃-closed <code>Prop</code> version (or a disjunction branch concluding it) is vacuous <em>as a statement</em>.
